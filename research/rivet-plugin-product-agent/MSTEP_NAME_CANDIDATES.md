# M-Step Name Candidates — Universal Plugin/Product Agent

Status: naming interlude before Research Pass 5  
Style target: Michael S. / M-Step — a joke or absurdly serious metaphor with a real technical/intellectual payload underneath it. The name should be memorable enough to smile at, but still encode what the agent actually does.

## Naming rule

Avoid generic job-title names like `Plugin Developer Agent` or `Product Engineer`.

Prefer the pattern:

`ordinary technical object or coding phrase + overqualified intellectual/strategic reference + useful second meaning`

The joke should survive contact with the documentation. If the name needs a paragraph to explain the joke, it is not sharp enough.

## Five finalists

### 1. Occam's Wrench
**Tagline:** Use the smallest wrench that fixes the machine — and do not remove the dashboard while tightening the bolt.

Why it fits:
- Occam's Razor supplies the simplicity/anti-overengineering reference.
- A wrench makes it a builder/repairer instead of a philosophy lecture.
- Encodes Rivet's core rule: smallest coherent repair, preserve the rest of the product.
- Works for plugins, extensions, userscripts, and integrations rather than only one browser technology.

Risk: leans toward repair more than greenfield product building.

### 2. Ctrl Freak
**Tagline:** Control the blast radius, not the user.

Why it fits:
- keyboard/control-system joke that immediately reads as software.
- the second meaning is exactly the agent's job: preserve product boundaries, runtime boundaries, evidence boundaries, and rollback boundaries.
- short, memorable, slightly mischievous.

Risk: `control freak` can sound negative unless the tagline/product copy lands the joke clearly.

### 3. Schrodinger's Plugin
**Tagline:** It does not work until the actual user opens the box.

Why it fits:
- directly encodes the Evidence Contract: synthetic tests do not equal field proof.
- perfect antidote to Ghost's repeated `tests passed -> field still broken` history.
- memorable intellectual joke with a real verification rule underneath it.

Risk: strongly verification-coded; weaker as the name of a full start-to-finish product builder.

### 4. Assembly Required
**Tagline:** Some agents write the parts. This one checks whether you still have a product when the screws are left over.

Why it fits:
- familiar consumer-product phrase with a software architecture second meaning.
- emphasizes that UI, runtime, exports, settings, adapters, diagnostics, tests, packaging, and novice UX have to become one coherent product.
- naturally fits the agent's whole-product integration role.

Risk: slightly less quirky than the other candidates and is a common phrase, so searchability may be weaker.

### 5. Patchology
**Tagline:** Diagnose the patient before prescribing another patch.

Why it fits:
- `patch` + `pathology`.
- captures Root Cause, preservation, Cleanerz, and the rule against fixes that merely fix earlier fixes.
- works for both new development and repair because the agent studies the whole system before changing it.
- has the same compact pun-plus-method feel as `R&Duck`.

Risk: could overemphasize bugs/repair unless the final description makes the product-building role explicit.

## Current read

For the final Pass-5 synthesis, do not automatically keep the provisional name `Rivet`. Re-evaluate it against these M-Step candidates and the Agents-of-AI naming lexicon.

A good final name must pass four tests:
1. funny or surprising on first read;
2. technically meaningful on second read;
3. broad enough for the full product-building mission;
4. short/searchable enough to function as an AoA agent name.
